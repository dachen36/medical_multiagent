# 未来计划

- [ ] **LLM Prompt 调优** — 针对 Qwen3.6-27B 优化各 specialist 的 system prompt，提升诊断准确性
- [ ] **WebUI 生产部署** — nginx 反代 + 静态资源托管，替代 Vite dev server
- [ ] **OCR 接入** — 安装 Tesseract，集成 `ocr_image.py` 到 intake 流程

- [ ] **chest-pain-triage 真实 LLM 验证** — 确认红旗场景在真实 LLM 下可靠触发 120 建议
- [ ] **多智能体日志增强** — 记录每个 specialist 的工具调用链和耗时

## 中期（1-2 月）

- [ ] **多轮对话支持** — intake-specialist 引导式问诊，根据患者回答动态追问
- [ ] **患者档案持久化** — 从文件系统迁移到 SQLite / PostgreSQL，支持多用户隔离
- [ ] **认证与权限** — WebUI 登录体系，不同角色（医生/患者/管理员）权限隔离
- [ ] **Docker Compose 一键部署** — 集成 FastAPI 后端 + Vite 前端 + 数据卷
- [ ] **自进化效果量化** — 设计评估指标，量化四级递进机制的实际效果
- [ ] **诊断结果回溯** — 支持查看历史诊断报告，对比自进化前后差异
- [ ] **更多 LLM Provider 测试** — 验证 DeepSeek / GLM / Moonshot 等国产模型兼容性

## 长期（3-6 月）

- [ ] **多语言支持** — 英文/日文诊断界面和报告输出
- [ ] **FHIR 标准接口** — 对接 HL7 FHIR，实现与医院信息系统互操作
- [ ] **联邦学习** — 多机构诊断模式共享，不暴露原始病历
- [ ] **移动端适配** — 响应式 WebUI 或独立移动应用

- [ ] **开源社区建设** — 文档国际化、贡献指南、示例项目、API 稳定化
